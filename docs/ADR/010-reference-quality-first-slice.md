# ADR-010：参考片对标的首个可执行短段

2026-10-10。决策：按用户“继续”推进已提交的对标设计，先冻结以下首轮契约再实施；保留旧方案。数据驱动、CLI优先，无新增生产依赖。

## 依据与范围

[对标与影响评估](../REFERENCE_BENCHMARK.md)已核对真实样片和当前实现。首轮交付是关键短段与相关执行能力，不是整个P0清单或商业母版验收。用户此前允许业务信息后补、先内审。没有新增音乐授权时使用原声/已有草稿声音，混音用显式技术信号测试。

## 冻结契约

- `schema_version:1`继续使用原schema，拒绝新增字段；`schema_version:2`复用v1基础结构并新增下述字段。未知版本与字段失败，不静默降级。
- `clips[].action_window`可选：`start/end`是源时间，`evidence`为已查看时序证据说明。区间必须完整落在所选片段内。程序只保证区间保留，不证明动作标签属实。等长替换必须显式提供并通过原动作约束，不能悄悄丢失保护。
- `overlays[]`最多40项，每项必需`id,start,end,text,fact_ids,kind,box,font_size,color`；kind为`emphasis/card/cta`，box为归一化`x,y,width,height`；可选`fade_in/fade_out`（秒）。文字按纯文本转义，不能注入ASS命令。图层在字幕上方、内审水印下方；框不得溢出安全范围，同时间相交的框失败。正文字幕保持独立SRT，展示字另存方案和ASS，不伪装成逐字口播。花字事实同样进入业务快照。
- `audio[].fade_in/fade_out`可选，秒，非负且两者和不得超过片段时长。默认0保持原行为。
- `mix.ducking`可选：`reduction_db`(-30至0)、`attack`(.01至2秒)、`release`(.01至3秒)。仅music在narration时间窗让位，重叠旁白采用最强一次衰减，不累加；属于区间驱动包络，不声称已检测句内停顿/实际说话声。
- `mix.loudness`可选：`integrated_lufs`(-24至-12)、`true_peak_db`(-6至-1)。使用本地loudnorm并在最终AAC解码后复测；无有效音频/非有限测值失败；目标偏差（响度1 LU、真峰0.2 dB）越界失败。指标不代替听审。
- 新API `allocate_actions(ranges, frames, fps=30)`：每个range需action_window且位于候选源范围；先保留起点到完整动作结束（向上取整帧），再按候选顺序延长至目标帧数，容量不足或目标过短失败。批次v2明确使用该分配器；旧v1均分保持可复现。旁白留白参数由批次显式给出，不默认把固定0.5秒作为审美规则。

## 实现路径与取舍

沿用ASS实现有限文字层；沿用FFmpeg volume/afade/loudnorm实现声音处理。音乐让位首期采用已知旁白时间窗，比实时检测更容易复现、测试；局限是长停顿不自动释放。后续确需侧链压缩再加明确策略，不为单一实现引入Provider。

代码：`presentation.py`校验v2扩展、`mixing.py`编译音频图及复测、`timing.py`动作分配；由现有contracts/captions/render调用。渲染内容指纹包含新字段和模块。字幕/混音变更复用原片段缓存。原片只读，不改原私有引擎，不将参考品牌音画用于新片。正式编码质量配置、静图、ASR/OCR生产接入、主体跟踪、机器语义证据核验暂不纳入。

## 测试与验收

先写边界测试：版本隔离、NaN/空/超长/越界、重复ID、文字框和时段碰撞、花字事实缺失、动作剪断、替换丢保护、容量不足、淡变超时、无音乐/无人声、重叠旁白、静音响度失败。合成正弦音验证让位量和淡变，实际字幕帧验证显示窗口；两者不替代视听。全套回归后，用真实原片产生5–8秒内审片、SRT、方案、技术QA及待听记录。

原片、库和旧方案无需迁移。新增字段参与校验与签名；新图层所用事实加入交付快照。Windows/Ubuntu组件CI加入新测试，当前macOS验证与未来远端验证分开报告。`agent env-check`本机不存在，doctor替代检查已执行，不记成前者通过。

官方实现依据：[FFmpeg滤镜](https://ffmpeg.org/ffmpeg-filters.html)、[ASS标签](https://aegisub.org/docs/latest/ass_tags/)。

## 实施证据

逐帧复查补充：首段计划79帧，固定引擎实际输出81帧（ffprobe），成片实际切点2.700秒而计划2.633秒。原因是上游无TTS分支仅在输入端使用-t，并用输出-r转换，未限制输出帧数。修复仍在现有适配边界内：已有v1/v2校验要求每段长度落在画布帧网格（容差1e-5帧）；v2把显式帧数传给隔离进程，仅为该次引擎切片命令添加输出-frames:v；随后核对实际解码帧数。v1不启用这一选项，固定私有源码不改动。缓存加入帧数并已有适配器指纹失效。新增非整帧拒绝、命令边界及完整渲染切点回归；不增加重编码次数。影响仅v2切片适配和缓存；已有整帧校验不改变；不改库/授权/部署。

本机全套185项通过、1项跳过，覆盖96.24%；新增模块达到核心门禁。声音测试实际编码/测量，文字测试检查编码后显示窗口；v2完整管线回归验证最终QA、花字改动生成新版本且复用两个原片缓存。真实短段5.433秒/1080p已输出并做抽帧修订；最终AAC为−15.93LUFS、−2.95dBTP。首稿文字对比问题与单声道归一化滤镜协商问题均记录CHECKLIST。连续播放/听审、完整营销母版与本轮远端Windows CI仍待验证。

## 2026-10-10 短音乐段响度修复（实现前影响评估）

真实Touch选段18.6秒在单遍loudnorm后，最终AAC为-14.82 LUFS，超出-16 LUFS目标的1 LU容差（traceId=00853c02e85c43948dc980974f8be840）。保留失败产物与校验结果。决定沿用现有FFmpeg，以相同输入、淡变、让位及总时长先分析混音，再把实测I/TP/LRA/threshold/offset传入第二遍归一化；最终AAC仍执行原校验，不放宽阈值。

不改变EditPlan字段、原素材、业务信息或审批；多一次本地音频分析，日志保存在渲染目录，模块指纹使旧混音结果失效。静音/非有限测值仍失败。先添加变幅音频AAC实测与静音、无测量等边界回归，再修复、执行全套测试及六条真实成片复测。依据FFmpeg loudnorm官方双遍/linear参数文档。

实施复测：全套186项通过、1项平台测试跳过，覆盖96.29%。新音乐六场景成片最终AAC均通过原响度门禁，1080×1920/30fps，实际解码帧数与方案一致；本地证据位于outputs/review-new-music-scenes/verification.json。具体响度、版本和哈希逐片保存，抽帧检查与未完成的连续观看/听审分别记录，不构成发布批准。

## 2026-10-10 对话调优固化：实现前范围与影响

用户要求总结连续调优、更新代码/提示词/文档并上传。沿用已冻结数据驱动CLI与v2契约，不新增依赖、云Provider、Schema或审批流程。保留已实现双遍响度修复；将云音频作为宿主提供文件接入，明确speech仍为本地语音。Skill正文由write_skill_bundle.py维护，细则放既有引用及audio引用文件，同步两套宿主安装。

现有批量渲染脚本逐片校验，且重跑失败前可能留下上一轮render-progress.json。收敛为：1–24个显式子计划、先全部校验再渲染、当前尝试开始重置进度为[]、成功逐项写入原有数组格式，失败不把后续旧成片列为本次成功。输出不变；不调用云服务、不写批准。只支持单写者顺序执行，同一批次不得并发运行；源素材、引擎、渲染缓存均不改。异常测试先覆盖非法数量、后续计划无效、第二条渲染失败与重跑缓存返回、中文路径/UTF-8，然后实施并执行全量回归。旧文件可保留供比较，不能仅以文件存在认定本轮成功；自定义审阅文件仍须核对revision/哈希。

调研依据：FFmpeg官方loudnorm滤镜文档与本机`ffmpeg -h filter=loudnorm`确认measured_I/TP/LRA/thresh、offset、linear选项；MiniMax官方同步TTS文档确认音频输出、字幕选项与usage_characters。两者都不保证实际自然度或剪辑美感。官方入口：[FFmpeg](https://ffmpeg.org/ffmpeg-filters.html#loudnorm)、[MiniMax](https://platform.minimax.io/docs/api-reference/speech-t2a-http)。网络FFmpeg文档本轮超时，参数以本机官方工具帮助复核。
