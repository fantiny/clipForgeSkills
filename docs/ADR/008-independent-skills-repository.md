# ADR-008：独立保存 Skills 开发预览版

2026-10-10。用户授权把新系列上传至独立仓库 clipForgeSkills，与原 clipforge 区分。

决策：在当前技能工作区初始化独立 Git 历史，新建 fantiny/clipForgeSkills 私有仓库（与原仓库可见性一致），版本定位 v0.1.0 开发预览。包含九个 Skills、共享CLI、Schema、测试、工具与开发文档；不复制原仓库历史，不修改原仓库，不上传真实素材、内部视频、索引、运行时、缓存、原始运营文件或本地凭据。Word派生报告保留本地，Markdown开发指导入库。

依赖边界：代码仓库独立，合成引擎仍固定到原私有仓库77a7e73e1f898581d325f3070b574ea0894d8a76。没有在本次上传中移植或另分发引擎。首次安装需要原仓库读取权限或已有检出。

CI影响：旧流程匿名克隆私有引擎必然不可靠。默认执行不需要引擎的结构、契约/恢复测试及依赖审计；仅在仓库配置原仓库只读Secret CLIPFORGE_UPSTREAM_TOKEN 后运行全量引擎集成。不自动复制开发机登录凭据，不以基础检查通过替代完整检查。参考GitHub官方Secrets文档与actions/checkout私有多仓库说明（链接见README）。

验收：上传前本地120项全量回归通过、整体覆盖96.38%，核心覆盖门禁通过；远程SHA与本地HEAD比对后确认上传。真实视频完整视听、双宿主完整会话、H3–H5及本地模型适配仍保留未完成，不标记整个路线图完成。

## 2026-10-10 公开发布边界补充

按用户明确要求排除隐私及公司专用内容。保留本地副本后移出公司开发指导，将公开引用改为通用业务指导；移除本机身份路径、内网地址和品牌默认值。工具默认content_id前缀改为review、未知SKU改为pending-review，仅影响新编译且未指定ID的计划；已有计划/素材/缓存不迁移。展示页和Word标题改为中性说明，不新增配置接口或依赖。技能修改同步生成器与两个宿主安装，随后全量回归和公开树检查。

临时目录盘点：生产素材脚本含固定资产ID、文案和本地路径，属于公司专用；临时补丁/PR草稿、测试日志、第三方源码检出、依赖缓存和安装副本不作为项目新增源码提交。可复用批量渲染工具已位于tools/production。历史分支中已有的公司文件不能靠当前树清理消除；随后用户明确授权清理所有分支历史，执行结果见下节。

当前树验证：全量189 passed、1 skipped，覆盖96.29%；公开代码/文档中的已知公司标识、实际用户路径、内网地址与疑似凭据字面量检查通过，本地Markdown相对引用有效，两宿主Skill副本一致。公司指导备份与移出前Git内容逐字节一致。检查不保证检测所有隐私，也不扫描或清除远端历史。一般资产数据、锁定依赖、测试夹具和第三方引用按其用途区分，未将缓存或私有引擎作为补提交内容。


### 已授权历史清理结果

使用官方git-filter-repo 2.47.0，在独立镜像中移除公司专用指导的全部历史版本，脱敏实际用户路径、共享地址及品牌标识，将个人提交邮箱替换为既有GitHub隐藏邮箱。核对398个可达对象、251个文件版本，已识别标识未再出现；最新代码树与清理前已通过测试的脱敏树完全相同。3个远端分支以原子推送及逐分支force-with-lease更新，无标签；本地分支已同步，原始资料与历史备份保留在忽略目录。

GitHub旧PR引用不受分支改写控制，已确认旧PR仍可访问移除的历史文件。后续决策改为同名重建仓库，不提交Support申请：先备份本地Git与仓库元数据，从已合并main的受控文件导出干净代码树，复核后初始化单一main根提交；不迁入旧分支、PR、标签或Actions运行记录。源码、锁文件和通用文档保留，本地忽略的素材与业务资料保留在原工作区，不参与发布。

影响范围：新仓库有新的仓库ID，历史PR链接和CI运行链接失效；仓库级设置需重新核对。重建前盘点无Fork、Star、Release、开放Issue或Actions Secret。私有引擎CI仍需单独配置访问凭据，未配置时明确跳过。发布后核对仓库ID、唯一main根提交、代码树、旧PR及旧提交访问状态，再记录本地核验结果。

协作者必须重新克隆，不能合并或推回旧历史。本方案处理公开仓库及其可见引用，不宣称已清空第三方克隆或GitHub内部备份；参见[GitHub删除说明](https://docs.github.com/en/repositories/creating-and-managing-repositories/deleting-a-repository)和[恢复说明](https://docs.github.com/en/repositories/creating-and-managing-repositories/restoring-a-deleted-repository)。
