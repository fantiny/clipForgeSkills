# ADR-001：本地优先的视频生产 Skills

状态：Proposed。日期：2026-10-08。关联：[架构与证据](../ARCH.md)。

## 背景

用户希望把 ClipForge 的本地素材混剪能力转为 Codex / Claude Code 可调用的 skills，控制 AI token 与额外模型费用，并覆盖参考片拆解到成片交付。发布运营不在当前范围。

现有 CLI 与素材处理模块具备复用基础，但仅包装原有全自动入口，仍会保留内部重复语义判断、场景标签耦合和交付状态不明确等问题。

## 建议决策

1. 采用数据驱动、CLI 优先方式。宿主执行需求理解与语义判断，本地工具处理批量媒体操作，无需新增常驻业务服务。
2. 一个入口路由到按需加载的业务能力；流程配方、场景 profile、工具执行分别维护。子 skill 不默认启动子 agent。
3. 保存版本化 Brief、ReferenceRecipe、Asset/Analysis、StoryPlan、EditPlan、RunLedger 与 Review/Delivery。源媒体引用与成片时间线分离，最终渲染读取唯一时间线。
4. 素材分析与制作阶段使用依赖指纹缓存，局部修订只失效相关产物。模板路径可以跳过额外语义分析。
5. 普通素材剪辑优先复用 FFmpeg；图形动画按需使用 Hyperframes。仅对实际多实现的能力引入 Provider，依赖版本待环境验证后锁定。
6. 共享可移植 SKILL.md、工具与产物契约，Codex / Claude 特有安装和执行配置留在薄适配层。
7. 原素材与旧产物先经适配读取；保留现有 mediaops，当前制作流程不依赖运营服务。

## 备选方案与取舍

| 方案 | 收益 | 主要代价 | 结论 |
|---|---|---|---|
| 只给原有完整流水线加 skill 包装 | 改动小 | 隐式重规划、全量重跑与旧场景耦合仍存在 | 可作过渡，不作为目标架构 |
| 每阶段独立 agent | 角色分工直观 | 上下文重复、轮次与恢复开销；对机械任务没有必要 | 不作为默认 |
| 完整移植参考项目运行时 | 现成功能多 | 数据模型、许可证、部署与生成成本复杂 | 只借鉴与适配所需部分 |
| skill 直接临时拼命令 | 初期灵活 | 契约、恢复、验证和复现困难 | 仅用于受控探索 |
| skills + 本地 CLI + 文件契约 | 复用本地能力，阶段可缓存、可检查 | 需要清理契约与实现宿主适配 | 推荐 |

## 影响与风险

- 原有 script 阶段需要支持外部审定方案，防止再次重选素材。
- 素材 ID、标签来源和缓存版本需补齐；旧库迁移必须有真实样例与回退路径。
- 真实交付必须排除 fixture、no_media 等演示或跳过状态。
- 本地推理也占用硬件与时间；尚无性能或节省比例实测。
- 宿主 token 与外部 API 费用不能混为一项，无法获得的数据记录未知。
- 工程导出需独立验证目标软件及版本；可复现方案不等于原生编辑器工程。

## 冻结条件与验证

确认首批场景、交付类型；完成环境探测与技术栈记录；冻结最小契约及失败状态后，才进入模块实现。

首个验证必须是实际参考片与本地素材组成的完整成片闭环，并证明缓存复用、字幕局部修改、缺素材失败、真实输出检查及两个宿主的契约兼容。具体质量与性能阈值根据样例和基线确定，不预先虚构。

当前仅提交设计草案，未表示用户已批准此 ADR，未执行迁移、依赖安装或业务代码修改。
