## 4. 各维度的对标要求

### 4.1 文案：每句话完成一个观众任务

当前种草片用“这一盒，先看细节”“把镜头拉近”等导览句；促销片使用“价格、时间和门店确认后一起告诉你”。它们适合此前信息未齐时的内部预演，但不足以成为正式推流母版。

修改方向：从本次提示词提取一个主要受众问题、一个核心购买理由、两至三个可支撑理由和一个CTA；让文案承诺与可用证据共同决定结构。对已明确的商品/价格不反复追问。信息待确认放在制作注释和内审标识里；正式口播需要改成观众关心的信息，不能把工作流程说明当卖点。

若暂时只有外观素材，可做实物细节/使用演示配方；不要为了“更有销售力”虚构气味、猫狗喜好、健康改善或优惠。镜头中有商品也不意味着它证明同一句话里的所有主张。

### 4.2 画面与图片：增加组织能力，保留实物可信度

两条参考主体都是实拍视频；A的超短首图不说明应该大量使用静图。优先补：主商品、细节、完整动作、结果、组合陈列、使用情境等镜头职责。给素材增加动作开始/关键时刻/结束、主体区域、文字避让区、可解释主张及不可支持主张。

需要活动组合图、规格卡或实物照片时，再支持PNG/JPEG/WebP导入、持续时间、适配方式、透明图层及有限位移缩放。素材只匹配到一句话的一部分时，返回缺口而非补一张无关美图。图形表达不能冒充产品实拍证明。

主体构图需提供contain、cover和可指定焦点/区域的裁切；开盒看盒内、喂食看嘴与餐盘、包装看标签。先支持人工/宿主指定关键区域与关键帧，自动跟踪后续按收益扩展，不必第一版引入复杂模型。

### 4.3 文案、画面与节奏：先确定关键时刻，再分配时长

现有`allocate()`先给每个候选片段0.5秒，再轮询分配到语音总时长；它保证容量，却不知道揭膜何时露出内容、指示棒何时到达文字、赠品何时完整入画。每段配音固定额外留0.5秒，也容易产生重复停顿。

新设计使用三类时间：原素材动作时间、实测语音词句时间、成片帧时间。编译优先级为：事实/语义与动作完整性 → 重点可读 → 声音表达 → 可选音乐节拍。不是将每个切点机械吸附到鼓点，也不是一条字幕必须对应一个镜头。

切点检测阈值0.23的初筛显示，排除尾板和A首图后，A候选视觉段通常约1.2–2.7秒；B有更短的0.47–0.73秒组合展示候选，也保留约2.6秒使用展示。该结果来自场景分数与图像抽查，**不是全量人工核准镜头数，也不是必须照搬的节拍标准**。8.2秒彩纸误报已经说明仅靠分数不够。

每段要能声明：关键动作必须完成、哪个词前/后出现主商品、文字最少展示多久、允许的音画先后关系、哪里可以换补充画面、哪里必须同一次连续动作。容纳不下时改短文字、补镜头或调整结构，不循环、不随意截断动作、不默认加速人物动作。

### 4.4 字幕与图形：常规阅读层、重点层、交易信息层

A有常规白字、颜色区分的成分词及动态卖点字；B用统一红粉色强调优惠和商品项。当前只有全片一个字体/字号/颜色和固定底部位置，无法表达这些关系。

第一版建议仅提供四类组件：普通句子字幕、短关键词强调、规格/组合/优惠信息卡、CTA。支持每条样式引用、局部词语颜色与粗细、区域定位、入退场、持续时间和层级；字体颜色受品牌主题控制。默认轻量动效，少量淡入/位移/缩放即可，不先追求转场库。

底部阅读字幕和卖点卡可同时存在，但应检测主体遮挡、重叠及平台界面安全区域。跨Windows/macOS需要字体文件或受控字体配置、实际字形测量及缺字检测，不能继续只用字符数乘字号估算。SRT保留纯文字阅读稿，视觉样式保存在ASS/方案中。

### 4.5 配音：从系统语音占位升级为可表演的段落

当前系统TTS按beat生成，且`alignment=not_computed`。本轮ASR能得到两条片子的口播候选序列，但错词明显，因此ASR只能作为时间参考与核对入口。

首选流程：整段或语义段录音/高质量已配置TTS → 核对文字 → 词句对齐 → 安排镜头与字幕。脚本保留重读词、停顿、读法和情绪目标；字幕可以精炼，但不能改变原意。保留现有本地系统语音作草稿选项，最终声音由实际试听决定；可用已有配音达到质量要求，不强制引入付费云服务。

不能从ASR认出完整句子就断言人声自然、字音正确或已完成听审。

### 4.6 音乐与音效：已有轨道，需要补编排和混音

`audio[]`已支持narration/music/effect和固定gain_db，`final_pass()`会延时后amix；现有六场景中的种草、促销方案都只有四段narration，并把实拍原声静音。不能把“底层能叠音频”写成已经具备完整声音设计。

|任务|需要的设计|验收方式|
|选乐|本地已授权乐库记录情绪、强弱、有人声与否、可用段落、许可范围；先为本片选择少量候选|原速试听口播与音乐组合，关注是否抢字、是否符合场景；不从波形猜曲风|
|音乐结构|音乐进入、持续、让位、退出与影片段落对应；必要时按音乐乐句截取和交叉淡化|片首不突兀、片尾不生硬截断、跨段无突跳；不把整首随机截一段铺满|
|音效落点|揭膜、颗粒落盘等同期声；卖点出现可选一个轻提示；分别记录真实原声与设计音效|对着动作关键帧检查同步，确认不会让观众误认产品声音或夸大实际表现|
|混音|人声、音乐、同期声、强调音效分别成组；音量包络、淡入淡出、人声出现时音乐降低、最终真峰控制|双声道和单声道、耳机和手机外放都需试听；不能只检查“存在音轨”|
|自动化|本地FFmpeg进行侧链压缩/音量包络、响度扫描与归一化，保存参数和统计|测量原始混音与AAC最终交付件；审核记录绑定最终revision|

本次下载件全文件FFmpeg ebur128测量：A为**−8.6 LUFS、LRA 3.4 LU、真峰估计+2.4 dB**；B为**−10.4 LUFS、LRA 2.9 LU、真峰估计+1.1 dB**。这是解码后的下载副本（含尾板），不代表原始母版；不能仅据此断言听起来失真，也不建议复制这种响度。正式片可先试验−16至−14 LUFS、真峰≤−1 dBTP，再按实际平台与听审调整；这是项目试验起点，非抖音强制规范。

尚待实际听审：背景音乐是否存在/何时进入、具体音乐段落、A倒粮是否保留原声、B彩纸是否配音效、是否有音画提前/滞后、是否遮蔽口播。不能因画面有彩纸就登记“有礼花声”，也不能把语音重音当鼓点。

### 4.7 高品质画面：控制完整渲染链

优先以原片输出1080×1920；帧率结合源片，现有30fps可作首期配置。2160×3840只有在原料和交付场景确有收益时启用，不用插帧或放大数字充当品质提高。

现实现按片段编码，再进行最终字幕/音轨合成编码；编码质量参数未在方案中显式冻结。应增加渲染配置：预览代理与正式原片分离、编码器/CRF/preset/色彩空间/字体版本明确、缓存依赖纳入配置、避免反复有损重编码。可先测试H.264 CRF18–20，结合真实纹理和文件大小选择，不能把参数值当视觉验收。

元数据应补rotation/display尺寸、SAR、色彩原色/传递函数/矩阵和HDR标识；仅当输入需要时做明确的色彩转换。曝光/白平衡匹配围绕同一产品实际外观，不过度锐化、磨皮、提饱和或改变食物颜色。画面清晰之外，还要检查关键内容是否一直在裁切范围内。

|P0|内部片actual_shots可能只覆盖候选区间前部，QA不核对语义关键帧|动作完成检查和带时间点的修复问题，阻塞问题绑定交付版本|图像、文案、声音一起验收，修订后旧批准失效|
|P1|`library.EXTENSIONS`不含静图，EditPlan只有顺序clips|支持静图/透明叠层/有限运动及规格卡|活动组合/规格说明可重建，使用高清源图，参考品牌图片不混入|
|P1|片段统一cover中心裁切，probe只有编码宽高|补显示方向、焦点/区域裁切、画面适配策略|包装字、揭膜动作、宠物嘴与餐盘按镜头目的保留|
|P1|编码参数隐含、可能多次有损编码|显式质量配置、色彩处理与原片正式渲染|代理不进入正式交付；细节/文字经过实际画面验收|
|P1|批次范围主要由宿主遵守；检索为已有标注关键词|本批次asset白名单强校验，动作/视角/可用区域与拍摄组关联|本次输入能独立制作，连续动作不跨不相关包装/场景拼接|
|P2|图形引擎未接入|在证实FFmpeg/ASS无法满足某具体片段后适配Hyperframes等|只增加已证明需要的复杂图形，不让普通混剪多一层运行时|

这些能力不需要拆成更多常驻agent或独立系统。优先扩展现有九个skill及本地工具；项目级代码不能靠新增几段提示词替代。

## 6. 提议的数据和执行设计

本节是待冻结设计，不是可直接提交给当前CLI的JSON。当前EditPlan v1保持兼容，涉及接口的实施前应写ADR、冻结边界和异常用例。

1. **ReferenceRecipe**：正文范围；事件的源时间、类别、观察、证据文件、置信/未审状态；机制解释；可迁移关系；不迁移项。下载噪声、尾板、片头残帧独立记录。ASR/OCR/画面观察分别有来源，不能相互覆盖成一份“绝对真值”。
2. **StoryPlan/beat**：观众问题、目标理解、口播、展示文字、事实ID、镜头候选与证据关系、关键动作锚点、声音意图、成功条件。价格/数量由本次简报统一驱动多个文字位置，防止一个地方改价、另一个地方仍是旧价。
3. **编辑契约扩展**：保留主视频序列，增加有限视觉层和音量包络；统一稳定ID与成片帧时间。上层使用词/动作锚点，下层编译成确定时间；源片时间与成片时间分别存储。可先定义EditPlan v2及v1适配，避免让v1静默接受原来无效的字段。
4. **ReviewIssue**：定位beat/层/音轨、输出时间、实际证据、问题影响、修改哪个输入、复查方式。原有creative-state可以承载意图；新增执行门禁将blocking问题和输出revision关联，不能仅靠自由文本“已修好”。

最小beat示例：目标为让观众看清本批次实物质地；口播使用已确认或可观察描述；选片绑定一个完整揭膜区间和一个细节区间；在内容露出时开始重点文字，留够阅读时间；揭膜原声可保留并让音乐降低；动作没完成/主体被遮/无声称依据任一存在则返回具体问题。这里不预设某个已入库文件一定有完整动作。

时序编译需处理：录音变长、零长度/重叠区间、变帧率、90/-90/180旋转、短动作、文字过长、多声轨同时进入、字体缺失、静图无时长、跨平台路径以及素材改动后的缓存失效。不能因参考中出现约0.47秒镜头就全局取消现有0.5秒限制；先定义短插镜用途、最少帧数和可读性规则。

不先引入任意轨道编辑器、自由动画脚本或自动主体跟踪。只有真实验收案例需要的字段进入首期契约，避免重复造独立剪辑软件。

## 7. Skill提示词与Harness需要改变的实际行为

|Skill|新的决策要求|本地执行和恢复|
|---|---|---|
|reference|每段同时回答“说什么、看到什么、文字如何强调、声音已知什么、何处推进”；未知留空|一次批量提取，按内容哈希/工具版本缓存；只把关键区间送宿主判断|
|library / tag|按本次批次找可完成任务的连续区间，而非只有“食物/宠物”标签|返回有限候选、动作节点、构图与缺口；补拍清单直接说明缺哪种证据|
|story|先输出少量有不同购买理由的开场，再选择一条兑现得了的路线；逐句绑定画面职责|保存确定方向；改价格只更新相关卡片/话术，改口播才使对应音频和对齐失效|
|audio|输出声音设计表：口播、音乐段、同期声、强调音效、各自何时让位|使用已配置且可用的录音/本地工具；没有音乐授权或声音能力时明确缺口|
|edit|由语义/动作/语音确定切点；先证明最难的5–8秒|先静帧验证构图，再短段验证时序/声音；有效部分锁定，只重渲染受影响片段|
|review|先看实际成片再读作者解释；分别核对静音能否看懂、只听能否听懂、音画合看是否互相支持|每个关键问题有证据和输入归属；修复后复查相邻衔接；不靠自评打分自动通过|
|deliver|正式原片渲染，验收绑定最终版本|技术检查、事实检查和实际视听记录分开；缺听审保持pending|

承接此前参考项目研究：Hypit的语义锚点应落实为编译依赖；OpenMontage的风格约束收敛成少量配色/层级/密度规则；DramaClaw的修复计划落实为字段白名单和实际局部修改；花叔的一帧/短段证明用于关键构图与运动；Hyperframes的相邻衔接复查用于修改后的片头/片尾。只借鉴机制，不宣称这些项目已经集成，也不把其效果阈值移作本项目质量标准。

低成本顺序：一次本地分析 → 复用摘要 → 有界候选 → 关键帧/短段语义判断 → 本地编译渲染 → 有针对性的复查。复杂声源分离、向量模型、视频生成和云端TTS不作为默认依赖；确有收益再启用，并记录时间、存储和外部费用。宿主token不可获取时记unknown，不能声称零成本。

## 8. 开发推进与成片验收

建议先做“实物细节＋使用动作”的一条20秒左右母版；长度是起点，最终由有效信息和完整动作决定。优惠资料齐全后，再派生“主品＋组合/赠品”的促销版本。六类场景不必同时重写，避免把未验证的节奏批量放大。

|阶段|交付物|可以进入下一阶段的证据|
|---|---|---|
|D0 对标与契约|本报告、待听清单、一个目标母版简报、接口ADR及影响评估|创作目标和本期字段冻结；已有信息不重复索取|
|D1 关键短段|5–8秒：一个核心理由、一段完整动作、一次重点文字、一次声音配合|在实际大小画面及实际声音上成立，缺项直接修，不能由帧图代替听审|
|D2 单条母版|完整MP4/SRT/可复现方案，正文与CTA有效|完整视听；价格/规格/主张对应来源；没有关键动作截断或遮挡|
|D3 修改与复用|改开头、改一句口播、改价格、换BGM四个案例|不相关选择保持；相关音画/字幕/QA重算；旧批准不复用|
|D4 跨平台与扩场景|Windows/macOS相同输入与品牌配置，随后扩六配方|分别验字体、音频、构图和交付；不要求不同平台输出字节相同|

可执行检查：正式片1080×1920与选定帧率、可解码、无意外黑帧/静音、字幕/声音不越界、资源与版本完整；叠层无边界溢出；字体无缺字；最终音频达到本片约定响度/真峰范围；素材与事实引用未过期。自动检查不直接证明“好看/好听”。

内容验收：每句核心主张都有合适的事实/演示依据；开场承诺在后文兑现；观众能说明产品是什么、值得了解的理由、下一步做什么；动作完整、重点可读、音乐不盖人声、结尾没有被切断。由指定审核人实际观看/试听，写下具体问题，不能自动填“通过”。

比较方法：在同一批素材、业务信息和成片长度约束下，保留现有版本作为基线，制作增强版；隐藏版本名称随机观看。先比较信息理解、画面证据、字音清楚、节奏停顿及具体偏好原因；没有真实投放实验，不以点赞/转化提升作开发验收承诺。记录首次分析与复用/局部修订耗时，不能以测试数衡量创作完成度。

|影响面|需要评估的变化|保护与验证|
