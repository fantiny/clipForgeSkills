# 以实际成片决定下一步

用于新片或内容含义的修订。只查素材、改颜色时直接用相应能力，不启动完整创作流程。

## 先定义观众得到的结果

明确受众、看完要理解/完成的事、当前事实和限制。把“高级、吸引人”转成可检查的表达，例如“看清袋口如何封好，知道完成后的状态”。种草要展示真实商品与适用价值；科普要把问题解释明白；分享要有真实经历；促销要明确有效活动与限制；服务要能跟做；门店要给出本地适用信息。没有数据不承诺传播或转化提升。

每个关键段落确定：观众问题、实际表达、画面需要证明或解释什么、声音承担什么、怎样检查成功。画面可以是证据、解释、对比或环境，不必逐名词配一镜。若只因好看而选中却无法说明用途，重新检查选片；素材不足时收窄表达或列补拍，不循环任意素材凑时长。

## 先验证决定成败的那一段

找出不确定性最高且会影响整片的部分：操作是否看得清、包装文字能否读懂、长口播是否有画面支撑、切点是否截断动作。优先制作这部分的合法预览计划；单独短段时使用独立content_id并明确技术/业务用途，字幕和音频时间要重新校验。不确定性已解决则直接整片制作，不额外制造一轮审批。

先看实际帧/片段，再解释结果。用`evidence`近看动作和切点；需要听音频就实际听取。工具不能听或没有真实素材时，记录具体未验项，不用模型自评分顶替。技术色卡、代码测试和字幕存在不能证明真实服务步骤易懂。

## 问题必须落到修改与复查

采用“版本/区间→实际观察→对理解的影响→改哪个输入→保持什么→怎样复查”。例如实际看见字幕遮住封口动作，最小修改可能是缩短文案或更换同长度清晰镜头；不是加转场。事实超出依据要改表达或补依据；混音盖过旁白要检查声音。修改后查看问题区间、相邻衔接，并确认整片仍完成观众目标。

事实/授权错误、步骤错误、关键文字不可读、动作被截断、声音缺失等关键问题不能由画面漂亮抵消。重复两次无改进时重查问题解释或能力缺口，不通过无限添加效果来“修复”。最终检查实际正式片，不能沿用低清预览的批准。

## 保存和恢复创作上下文

有跨轮内容决策时，按`schemas/creative-state.v1.json`维护一份输入JSON：

- `result_contract`：观众及可观察目标；`locked_choices`：用户确定、不得自行改动的选择。
- `beats`：每段purpose/message/visual_requirement/audio_intent/acceptance及关联artifact_ids。
- `artifacts`：现有计划、事实、实际媒体或证据文件；`global_artifact_ids`标全片相关依据。
- `open_issues`：实际未决问题和下一项最小检查；缺片或缺事实直接记问题，尚无工件可使用空artifacts。已解决项从当前记录移除，历史快照仍在。

```sh
scripts/run.py creative-save path/to/creative.json
scripts/run.py creative-context CONTENT_ID --beat BEAT_ID
scripts/run.py creative-save path/to/creative.json --expected CREATIVE_REVISION
```

使用实际返回的ID；creative revision与render revision不同。工件相对路径以输入JSON所在目录解析。更新输入后需使用当前creative revision，冲突先读新状态，不强制覆盖。相同内容幂等返回；事实/方案/媒体内容变化会触发重新检查。

恢复时读限定段落的context：观众目标、锁定项、全片blocking问题始终保留；路径/哈希供按需读取，不把媒体内容全塞上下文。`stale_artifacts`非空先检查变更影响；超出字符预算时缩小段落选择或显式提高预算，不能删除硬约束换取成功。字符数不是Token。

`needs_recheck=false`只表示没检测到依赖变动、历史版本或blocking记录，不代表已看片、已支持主张或获批准。旧creative-notes可人工整理进新记录，工具不自动迁移。现有deliver尚未自动读取creative问题；宿主在安排交付前必须核对所有blocking项，再按真实review/status完成交付。机器级语义关联与问题修复门禁留到H3/H4。
