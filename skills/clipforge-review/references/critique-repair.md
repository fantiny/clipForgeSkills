# 把审片结论变成可验证的修改

先用用户目标、实际计划、相关事实和输出媒体评审；再读创作理由，避免只沿着作者解释确认“做对了”。这是同一宿主的自查，并非独立评测。复杂任务的独立评估只在获得相应授权后进行。

## 分三层检查

1. 技术：文件解码、时间/尺寸、字幕边界、音轨是否存在。CLI已检查的读取结果即可，不重做无关分析。
2. 事实与对应：主张是否被引用事实支持、画面/包装是否匹配、活动是否适用、需要完整展示的动作是否完整。引用有效不等于语义支持。
3. 表达：开场问题是否被兑现、画面是否帮助理解、重点是否有阅读时间、转折是否突兀、字幕与主体是否争抢注意力、当前场景是否需要CTA。

未知不得写通过；一次严重问题的存在不免除检查同类问题。主观分数不能覆盖事实/授权等阻塞项，也不能当成传播效果预测。

对切点、闪过的字幕或未完成动作，用 `scripts/run.py evidence <当前output.mp4> --start <秒> --end <秒> --every-frame` 提取问题前后的小区间。提取原片时记录源时间，提取成片时记录成片时间及revision；两者不能互换。每段最多120帧；音轨存在与解码通过只证明技术状态，实际听取仍单独记录。

## 可定位问题记录

在creative-notes记录：实际revision与时间段/字段 → 可核对的证据 → 具体后果 → 负责修复的输入 → 最小修改 → 保持不变项 → 如何复查 → 实际结果。

例如，确实查看到“5.2–6.1秒字幕遮住封口手势”后，不能只写“画面需优化”。指出受影响的操作，比较缩短字幕表达或选择能露出手势的等长片段。当前v1没有字幕位置patch，不要假造支持；对明确支持的字段使用revise，否则记录能力缺口或在授权范围内重新制订方案。

另一个例子：事实仅支持成分，字幕却承诺健康效果。问题属于文案/事实对应，不能靠换BGM、换镜头或换同义词修复。改为证据能支持的表达，并复查标题、口播和画面文字是否仍有同类主张。

## 修复归属与失效范围

|问题|应改的输入|需复查的内容|
|---|---|---|
|意图不对或开场承诺未兑现|创作方向/文案|整片叙事与所有受影响镜头|
|事实主张超出依据|文案或补充事实|字幕、口播、标题及活动有效性|
|选错素材或动作不完整|素材ID/源区间|该片段和前后衔接；原声关系|
|只改字幕颜色|style.color|可读性及局部输出；镜头/音频应复用|
|旁白改字或变长|权威文案与音频|真实时长、字幕、画面覆盖及相邻切点|
|解码/工具错误|执行输入或工具环境|对应技术检查；不无故重写故事|

修订前明确目标值和锁定项。v1的revise仅支持样式或一个等长镜头；能用patch就不要整份重新生成。修改后对比计划差异，先看片段前/中/后，再确认整片仍完成原目标。如果变差，保留原版并修正问题解释，不继续叠加效果。

两轮局部修订未解决时，保留问题和当前最好版本，说明缺失证据或能力；严重问题保持未通过。禁止因审核异常、模型返回空或达到重试上限而写批准。

只有实际完整看过/听过并完成必要核对，才能用现有review接口记录对应事实。一次抽帧、静音预览或自动化测试不能让watched/listened自动变成true。

## 局部修复后复查同类问题

检查主商品以外的价签、背景海报、邻近商品和动作结果。发现一处旧价格后，将同类检查覆盖当前选片；不要求用户重审整个素材库。等长替换要再核对画面能否支持当前话术，不能只验证时长。某次抽帧看不到价格不证明整段没有；快速闪现文字需缩小范围逐帧。

记录抽帧查看的实际时间、revision与文件哈希，watched/listened只反映实际完整观看/听取。新视频使旧审阅失效；复制到相同output.mp4路径不保留批准。技术通过时可以提供待听内审版，但明确配音自然度、音乐语义冲突、乐句收尾、参考片节奏尚未验证。
